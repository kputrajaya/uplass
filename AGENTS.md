# Uplass

Asset upload API, storage, and delivery for multiple apps. Apps swap an app key/secret for a short-lived token, then use that token to push one file to S3 and get back a public URL.

## Stack

- Go modules (`github.com/kputrajaya/uplass`), Fiber v3, GORM + pgx (Postgres, via `postgres.Open` DSN), AWS SDK for Go v2 (`service/s3`, static credentials from env), `godotenv`
- Multi-stage `Dockerfile`: `golang:1.26-alpine` builder, `scratch` runtime, `EXPOSE 8080`

## Layout

| Path | What |
| --- | --- |
| `main.go` | Fiber app, middleware (compress, CORS), routes, listen address |
| `handlers/handlers.go` | `Ping`, `GetToken`, `UploadAsset` + limits |
| `handlers/handlers_test.go` | Handler tests: guards + full flow on in-memory SQLite |
| `main_test.go` | Route wiring, CORS, listen-address selection |
| `utils/database_test.go` | `GetGDB` fatal paths (subprocess) |
| `utils/helpers_test.go` | bcrypt, RNG, S3 upload against a local HTTP server |
| `models/app.go`, `models/token.go` | GORM models (`apps`, `tokens`) |
| `utils/database.go` | Memoized `*gorm.DB` from env |
| `utils/helpers.go` | `HashSecret`, `VerifySecret`, `RandomString`, `UploadToS3` |
| `utils/helpers_test.go` | Pure unit tests |
| `commands/migrate` | `AutoMigrate` for both models |
| `commands/hash_secret` | Prints a bcrypt hash for an app secret — no DB access |
| `test.http` | Manual requests (REST-client format) |

## Commands

```bash
go build ./...                     # build all packages
go vet ./...
go test ./...                      # unit tests; DB cases skip unless env set
go run .                           # serve on localhost:8080, or :$PORT when PORT set
go run ./commands/migrate          # create/update tables
go run ./commands/hash_secret 'my-app-secret'   # prints bcrypt hash, no DB access

docker build -t uplass .
docker run --rm -p 8080:8080 -e PORT=8080 --env-file .env uplass   # PORT needed: default bind is localhost:8080
```

## HTTP API

- `GET /ping` → `Pong` (plain text)
- `POST /token` — JSON body `{"AppKey": "...", "AppSecret": "..."}` → 50-char token as plain text
- `POST /upload` — multipart `token` + `file` → absolute asset URL as plain text

Errors go through `fiber.NewError` with an explicit status; bodies are plain strings, not JSON — clients parse text.

## Invariants (do not regress)

- **Token lifetime** `TokenExpiryHour = 3`; **single use**: `used` is flipped in the same `UPDATE … RETURNING` that validates the token, so concurrent uploads cannot reuse it.
- Token is **burned even when the S3 upload fails** (deliberate — a failed upload returns 500, the token is already spent).
- **Max file size** `FileSizeMax = 10 MiB`; `BodyLimit` is `FileSizeMax + 1 MiB` in `main.go`.
- **Secrets are bcrypt hashes** (cost 12, `secretHashCost` in `utils`) generated by `utils.HashSecret`, verified with `utils.VerifySecret` → `bcrypt.CompareHashAndPassword`. Salt is embedded in the hash; nothing else is stored. No legacy sha256 hashes are accepted — old rows must be re-hashed: `go run ./commands/hash_secret '<secret>'`, then `UPDATE apps SET app_secret = '<hash>' WHERE app_key = '<key>'`.
- **S3 key layout** `<app_key>/YYYY/MM/DD/<5 random chars>/<original filename>`; the response URL is `ASSET_HOST + prefix + filename`.
- `RandomString` concatenates `crypto/rand.Text()` (unbiased uppercase base32) and truncates, so the 50-char upload token and the 5-char path segments are unpredictable. Don't swap it back to `math/rand` or a hand-rolled modulo pool.
- `utils.GetGDB()` memoizes one pool via `postgres.Open(PGSQL_CONN_STR)` (pgx); it `log.Fatal`s if `PGSQL_CONN_STR` or `PGSQL_MAX_OPEN_CONNS` is missing/bad. Don't hand it a `database/sql` pool from another driver — the postgres driver speaks pgx and placeholder counts break.
- `var uploadToS3 = utils.UploadToS3` in `handlers` is the test seam — keep it a package variable, tests replace it.
- `var getGDB = utils.GetGDB` in `handlers` is the database seam — tests swap it for in-memory SQLite; production always uses the env-driven Postgres pool.
- App deletion is a GORM soft delete: a token whose app is gone must fail the upload with 500, not silently succeed.

## App provisioning

`commands/hash_secret` only prints a bcrypt hash — it never touches the database. Insert the app row yourself:

```sh
go run ./commands/hash_secret 'the-app-secret'   # → $2a$12$...
```

```sql
INSERT INTO apps (app_key, app_secret) VALUES ('the-app-key', '$2a$12$...');
```

`app_key` is `uniqueIndex`; to rotate a secret, `UPDATE apps SET app_secret = '<new hash>' WHERE app_key = '<key>'`. The secret appears in the process arguments, so avoid it on shared machines and keep it out of shell history recording if that matters to you.

## Config

Copy `.env.example` to `.env` (gitignored) and fill:

```
PGSQL_CONN_STR          # postgres://user:pass@host:port/dbname
PGSQL_MAX_OPEN_CONNS    # integer, e.g. 10
AWS_BUCKET              # bucket name
AWS_REGION              # e.g. ap-southeast-1
AWS_ACCESS_KEY
AWS_SECRET_KEY
ASSET_HOST              # public base URL, include trailing slash
AWS_ENDPOINT            # optional: S3-compatible endpoint (MinIO / test server); path-style is enabled with it
```

`main.go` and `commands/migrate` call `godotenv.Load()`, so `.env` in the working directory is picked up; `commands/hash_secret` reads no environment. Never commit real values or bucket credentials.

## Testing notes

- No server, no CGO, no env vars: `go test ./...` runs everything. `handlers` swaps the `getGDB` seam for `github.com/glebarez/sqlite` in `:memory:` (single connection so the DB survives the test), so the whole token/upload flow — bcrypt verify, token creation, single-use marking, expiry, burned-on-failure, soft-deleted app — is covered without Postgres.
- S3 is exercised against an `httptest` server via the optional `AWS_ENDPOINT` env var (also usable for MinIO); the normal upload path still goes to AWS.
- `GetGDB`/`UploadToS3` fatal branches run in a child test-binary process, since `log.Fatal` would kill the test runner.
- Still only verifiable against a real deployment: real Postgres quirks (pgx DSN/TLS), real S3 credentials and bucket policy.

## Conventions

- Never hand-edit `go.mod` / `go.sum`; `go.mod` declares `go 1.26.0` and the Dockerfile pins `golang:1.26` — bump deliberately, not as a drive-by. Several deps (`golang.org/x/*`, `fasthttp`) already require 1.26, so the directive cannot go lower without downgrading them.
- Keep `main.go` route table and `newTestApp()` in `handlers/handlers_test.go` in sync when adding routes.
- Untracked: `.env`, build output, `*.log`, `.vscode`, `__debug_bin` (see `.gitignore`).
- `sample-image.jpg` exists for `test.http` uploads — it is test data, not an asset to serve.
